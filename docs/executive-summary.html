EXECUTIVE SUMMARY · HOW TO SUBMIT

Making a submission to the GEMS Prize

Each step cites the official page it comes from. Quotes were copied from pages fetched on 2026-10-20 and are listed in the source ledger. Anything not checked is marked as such.

1. The file you upload

  1. One GeoTIFF with one band, float32. The problem page requires “a single layer with datatype of 32-bit float (float32)” (problem page).
  2. Values between 0 and 1. “with values between 0 and 1 indicating the confidence or probability of fault presence” (problem page). Our file: minimum 0.0, maximum 0.99998, 0 NaN values, 0 positive values outside the footprint (LOCAL-FORMAT-VALIDATION).
  3. Projection and grid. EPSG 32611 (UTM zone 11N), 100 m, same bounds as the training data (3,730 rows × 3,292 columns). The validator reports that the transform matches the sample submission (validator output).
  4. Outside the bounds. The problem page says “data outside the bounds is null or nan.” Our shared writer writes 0 outside the footprint, not NaN. Whether the portal accepts that is not verified. See the limitations page.

2. The “Predicted values must be in range [0, 1]” error

This is the message you reported from the portal. We cannot see your earlier file, so we cannot say which value caused it. Our generated file has no value outside [0, 1] and no NaN, as shown above. Before uploading any file, check it for raw features (for example a nodata value such as −3.4028e38), unnormalized scores, and values above 1.

3. Name and note

Our file is named gems70-c1-strike-catalogue-NOT-CLEARED-20261020 (47 characters). A prepared note is 88 characters. The portal’s upload form and its length limits were not visible in this environment, so they are not verified.

4. Rules that apply

  • Weekly limit. “three submissions per week” (rules §3.2; §3.4 says “up to three per week, as specified on the competition website”). Rules PDF.
  • One final submission. “By the submission deadline, you must select only one set of predictions to use as your final submission” (rules §3.4). §3.5 adds that the choice is made “before the end of the competition”. The choice must be made without knowing private scores (§3.6.2).
  • Deadline. The competition page gives “Dec. 3, 2026, 11:59 p.m. UTC”. Rules A.1 require posting “by 5:00 p.m. ET on the prize submission deadline date”. On Dec. 3 that is 22:00 UTC, which is earlier. Plan to the earlier cutoff. This is a discrepancy to confirm with the organizers.
  • Generative AI. You “must indicate in the narrative” the extent of any generative-AI use (rules §3.2). The code and text in this repository were produced with AI-agent assistance. The disclosure must be written and checked by you before any submission.
  • Eligibility. An individual must be “a U.S. citizen or permanent resident”; private entities must be “incorporated in and maintain a primary place of business in the United States” (rules §1.3). This is not checked here. Confirm it yourself.
  • External data. Allowed only if you hold a license and the data “must be shareable with the challenge organizers” (competition page).

5. The upload steps

  1. Enroll on the competition page with the “Compete!” button in the sidebar (step 1 of “How to compete”). The data tab requires a login (checked: redirect to login).
  2. Click “Submit” in the sidebar, then “Make new submission” (step 6 of “How to compete”).
  3. Choose one GeoTIFF file that passes section 1 and enter the note. Keep the portal receipt (score shown and time).
  4. Choose your final submission before the deadline (section 4). Only the portal receipt can be called ORGANIZER-CONFIRMED.
