How a future eligible submission works

Do not use this negative run. The unresolved protocol decision explains why a new, nonempty submission cannot pass the current literal uniqueness test. The workflow below applies only after a fresh candidate passes every scientific and publication gate. This static website reports precomputed evidence; it does not train a model in your browser.

  1. Check the readiness banner. Only a released artifact may receive a TIFF download link. A valid format alone does not mean it is unique or worth a competition slot.
  2. Verify scientific clearance. Feature canaries, same-split current-best improvement, a complete pre-placement surface audit and final-dot audit must pass. The present experiment fails and stops before the last step.
  3. Package with the shared writer. A single-band float32 GeoTIFF must match the sample CRS, shape and geotransform. The writer rejects non-finite/out-of-range values rather than silently clipping them; this project also sets outside-footprint values to zero.
  4. Validate exact file bytes. Reopen the TIFF, verify range, footprint and mapped-fault masking, and record its SHA-256. A ZIP must contain exactly one TIFF. Our shared writer checks that round trip.
  5. Obtain separate slot selection. Check the current submission page's rules and remaining weekly allowance; it is not known in this sandbox. Local candidate promotion does not authorize an upload.
  6. Upload only the released TIFF or one-TIFF ZIP. At the official competition site, open New submission, choose the file and copy its short identifying note. A JSON report, HTML page or PDF is not the prediction file.
  7. Keep the organizer receipt. Only an actual submission-page receipt can establish an ORGANIZER-CONFIRMED score. Save filename, hash, time, note and receipt together.
